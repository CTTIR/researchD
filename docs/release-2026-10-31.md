# Connected release audit — 31 October 2026

Baseline: researchD `e510bc3`, researchR `a3e6e1f`, both clean and matching
GitHub main. The rename to researchD is present locally and on GitHub.
The preceding revisions passed their hosted workflows (server three jobs,
client six jobs). Those results establish a baseline, not proof of this release.

The target is a dependable, single-host academic surveillance service and its
API v1 client. Scientific coverage and classification still require human
review. This release does not add new sources or claim validated clinical use.

## Strategy and acceptance

1. **Essential repairs:** close credential disclosure, browser cross-origin
   writes, OTP replay, concurrent duplicate sends and configuration data-loss
   paths. Acceptance: adversarial HTTP/concurrency regressions and compatible
   additive migrations in R and Python.
2. **Everyday use:** make fresh startup safe, preserve seed controls, expose
   corrupt configuration and incomplete upstream responses, keep RSS readable
   and client errors actionable. Acceptance: clean setup, repeatable export,
   real client HTTP round trips and invalid-input/failure checks.
3. **Release:** synchronize instructions and versions, build/install archives,
   run native and Docker checks, publish only the reviewed main revisions and
   preserve checksums and run receipts. Acceptance: exact source revisions and
   artifact contents linked to observed validation.
4. **Deferred:** scientific classifier validation, broader provider coverage,
   snapshot pagination, multi-host coordination, per-recipient email ledger
   and self-service authenticator replacement. These require distinct designs
   or external services and are not hidden requirements of this patch cycle.

## Use and upgrade

Follow the [README first-use commands](../README.md#first-run-on-this-machine).
`python3 scripts/setup.py` creates `.env` with mode 0600 and runtime directories
with mode 0700, generates private
credentials and refuses to replace an existing file. Initial questions are
empty; reviewed sample questions live in `config/questions.example.yaml`.
An empty pipeline is a healthy idle run. Compose project names are lowercase
and independent of the repository's mixed-case name.

For an existing installation, preserve `.env`, `db/`, `digests/` and reviewed
configuration, back up SQLite and its matching encryption key, then rebuild
all three services. The new `auth.totp_last_step` column is additive. A code
used to complete enrollment cannot immediately log in a second session; wait
for the next authenticator code. Recovery codes remain single use.

## Operational boundaries

- SQLite and sender locks require local, single-host storage. No multi-host
  or high-volume performance claim is made.
- SMTP and file delivery remain at least once if a process fails after the
  external side effect but before database acknowledgment. Partial SMTP
  recipient acceptance can duplicate already accepted recipients on retry.
- Feeds are public, bounded views. Offset API pagination is not a snapshot.
  Source coverage, credentials, quotas and classifier accuracy vary; inspect
  source health and review the underlying evidence.
- Real provider credentials, external SMTP/Zotero receipt, public TLS and a
  production scheduled cycle require deployment-specific validation.
- Browser automation was unavailable on this machine. Real HTTP enrollment,
  recovery and client journeys plus executable dashboard DOM tests provide
  functional evidence; visual/accessibility review remains unperformed.
- Password/TOTP rate limits are process-local. Use a TLS reverse proxy and
  persistent request limits for a public service. Authenticator replacement
  currently requires an administrator recovery procedure; keep the enrolled
  device and recovery codes available.
